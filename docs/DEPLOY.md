# Deploying ClubHub for free

Every service below has a free tier that needs **no credit card**. Nothing here can bill you.

```
 browser ──► Vercel (React, CDN) ──/api/*──► Render (Spring Boot, Docker) ──► Neon (PostgreSQL)
    │                                            │  └──► Upstash (Redis, rate limits)
    └──────────── wss://…/ws (live) ─────────────┘     (domain events delivered in-process)
```

| Piece | Service | Free tier (Sep 2026) | Trade-off |
|---|---|---|---|
| Frontend | [Vercel](https://vercel.com) Hobby | 100 GB transfer/month | Personal / non-commercial use only |
| API | [Render](https://render.com) free web service | 512 MB, 750 h/month | **Sleeps after 15 min idle**; first request then takes ~30–60 s |
| PostgreSQL | [Neon](https://neon.tech) free | 0.5 GB | Compute pauses when idle (wakes in ~1 s) |
| Redis | [Upstash](https://upstash.com) free | 256 MB, 500K commands/month | Enough for rate limiting |
| Events | in-process (no broker) | | One instance, no retries/DLT; Kafka is optional via the `cloud-kafka` profile |
| Files / email | not used | | Poster uploads need S3; email stays in `log` mode |

Free tiers change. Check each pricing page before you rely on it.

## 1. Database: Neon

1. Sign up at neon.tech (GitHub login) → **New project** → name `clubhub`, region **AWS Asia Pacific (Singapore)**, Postgres 18 (or the newest offered).
2. **Connect** → turn **Connection pooling OFF** (you need the *direct* host, without `-pooler`).
   ClubHub switches `search_path` per tenant on each connection; a transaction-mode pooler would leak
   it between clients.
3. Note the host, database, user and password. The JDBC URL is:
   `jdbc:postgresql://<host>/<database>?sslmode=require`

Flyway creates every table on first start; each new club gets its own schema automatically.

## 2. Redis: Upstash

1. Sign up at upstash.com → **Create database** → type Redis, region **ap-southeast-1 (Singapore)**, TLS on.
2. Copy the **Redis URL** from the "Connect" tab. It looks like
   `rediss://default:<password>@<name>.upstash.io:6379` (note `rediss`, with TLS).

## 3. Kafka (optional)

The free deployment runs **without a broker**: `application-cloud.yaml` sets
`clubhub.events.transport=in-process`, so after each commit the app calls the inbox, WebSocket and
email handlers directly (`InProcessEventRelay`). Local development, Docker Compose and the test suite
still use real Kafka. (Aiven's free Kafka tier was "not available due to high demand" in Sep 2026.)

To use a hosted Kafka later (e.g. Aiven): create topics `clubhub.domain-events` and
`clubhub.domain-events-dlt` with 2 partitions, set `SPRING_PROFILES_ACTIVE=cloud,cloud-kafka` and add
`KAFKA_BOOTSTRAP_SERVERS`, `KAFKA_ACCESS_KEY`, `KAFKA_ACCESS_CERT`, `KAFKA_CA_CERT` (contents of the
service's `service.key`, `service.cert`, `ca.pem`). See `application-cloud-kafka.yaml`.

## 4. API: Render

1. Sign up at render.com with GitHub → **New** → **Blueprint** → select the `clubhub-api` repo.
   Render reads [`render.yaml`](../render.yaml): Docker build, free plan, Singapore, health check.
2. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` · `DATABASE_USERNAME` · `DATABASE_PASSWORD` | from Neon (step 1) |
   | `REDIS_URL` | from Upstash (step 2) |
   | `CLUBHUB_APP_URL` | your Vercel URL, e.g. `https://clubhub.vercel.app` (fill in after step 5; any value works for now) |
   | `CLUBHUB_ALLOWED_ORIGINS` | `https://clubhub.vercel.app,https://clubhub-*.vercel.app` |
   | `CLUBHUB_ADMIN_EMAIL` | the email you will register with (becomes platform admin) |

   `JWT_SECRET` is generated by Render. The build takes ~5 minutes.
3. Open `https://<service>.onrender.com/actuator/health`. It should return `{"status":"UP"}`.

## 5. Frontend: Vercel

1. In [`frontend/vercel.json`](../frontend/vercel.json), make the `/api/:path*` rewrite point to your
   Render URL if it is not `clubhub-api.onrender.com`. Commit.
2. Sign up at vercel.com with GitHub → **Add New… → Project** → import the repo →
   **Root Directory: `frontend`** (framework Vite is detected).
3. **Environment variables**: `VITE_WS_URL` = `wss://<service>.onrender.com/ws`
   (Vercel rewrites don't carry WebSockets, so live notifications connect to Render directly).
4. **Deploy**. Then put the final Vercel URL into Render's `CLUBHUB_APP_URL` / `CLUBHUB_ALLOWED_ORIGINS`
   (Render redeploys automatically).

## 6. First run

1. Open the Vercel URL → **Get started** → register with `CLUBHUB_ADMIN_EMAIL`.
2. In Render, **Manual Deploy → Restart** once: the admin is promoted at startup. Log out and back in.
3. **Platform** → **New club**. You are its admin; everything else works from the UI.

Tip: a free uptime monitor (e.g. UptimeRobot, 5-minute checks on `/actuator/health`) keeps the Render
instance awake during a demo or an event day. Render's 750 free hours cover one always-on service.

## Why these choices

- **Why not run the API on Vercel?** Vercel runs short-lived functions. ClubHub needs a long-running
  JVM: WebSocket sessions, Kafka consumers that poll continuously, a connection pool.
- **Why a `cloud` Spring profile?** Local dev and tests use plain Docker services; the free cloud
  services need TLS for Redis, a small connection pool and no broker (events in-process).
  [`application-cloud.yaml`](../src/main/resources/application-cloud.yaml) holds exactly those differences, all read from env vars.
- **512 MB:** the JVM is tuned for it in `render.yaml` (serial GC, capped heap/metaspace, small
  stacks). `docker compose --profile full` runs the API under the same 512 MB limit to prove it fits.
- **Rate limiting behind two proxies:** API calls reach Render through Vercel, so several users can
  share one egress IP. The per-IP login limit is raised to 120/min in `render.yaml`.

## Self-hosting instead (one VM)

With a VM of your own (any cloud or a spare machine with Docker, >= 2 GB RAM):

```bash
git clone https://github.com/Ayush0612005/clubhub-api && cd clubhub-api
export JWT_SECRET=$(openssl rand -hex 32) POSTGRES_PASSWORD=$(openssl rand -hex 16) WEB_PORT=80
export MONITORING_BIND=127.0.0.1                # Grafana/Prometheus only via SSH tunnel
docker compose --profile full up -d --build     # web :80, Grafana on 127.0.0.1:3002
```

Put a TLS-terminating proxy (or Cloudflare) in front of port 80 for HTTPS.
